# v0.8.0: A release may depend on an unratified decision only on recorded, expiring terms

The first release under [ADR-035](../adrs/035-a-release-may-depend-on-a-proposed-adr-only-on-declared-and-expiring-terms.md), and the first since v0.1.0 whose runtime depends on exactly the `Proposed` decisions its ratification record names. Every release from v0.2.0 to v0.7.0 depended on at least one unratified ADR, and v0.7.0 recorded nothing at all. [RATIFICATION-v0.8.0.md](../adrs/RATIFICATION-v0.8.0.md) records that now.

**Behaviour change:** `engine/manifest.py --validate` now **fails** a repository that declares a condition level or profile below its ADR-006 floor. If your CI runs `--validate`, see [the floor](#the-adr-006-floor-is-enforced-181) before upgrading.

## The release condition is settled (#223)

ADR-035 amends the condition "every decision the runtime depends on is Accepted". A release may depend on a `Proposed` ADR only if all of the following hold:

- the ADR is cited by code that ships, runs and governs (`engine/`, bound adapters, `tools/` except measurement tools, `.claude-plugin/`);
- the ADR declares the external evidence it waits for;
- the release's ratification record lists it with each condition's state and a release count;
- `conformance/skill.py` verifies the record against the tags;
- the dependency has lasted no more than two releases.

The old check read only `engine/` and bound adapters, which hid ADR-029 through eleven releases.

Applying it to this release:

- **ADR-029** (hooks) was reduced to what its evidence supports and accepted: the secondary delivery surface and its four constraints, blocking as a backstop, and the verified hosts (Claude Code, and Refact in a single agent chat). The cross-vendor claim is not accepted.
- **ADR-031** was reduced to the engine's rule for configuration gaps (reported, never blocking; a closed advisory set) and accepted. Its agent-disclosure obligation moved to the new **ADR-036**, which stays `Proposed` and which no runtime code cites.
- **ADR-033**'s single runtime citation, a comment, was reworded. Behaviour is unchanged.
- **ADR-034** (publication) ships as a recorded dependency for its second and last release before it must be decided.

## Refact is a governed host (#247)

[Refact](https://github.com/JegernOUTT/refact) joins Claude Code, Cursor, Codex, Gemini CLI and VS Code as a hook host: `tools/hooks/refact.json`, installed as `.refact/hooks.yaml`, with `refact` as a declared installer harness. Blocking was tested on Refact 8.6.4 against a real repository: writes without authority are refused, and writes under `CONTINUE` go through. Setup, verification and troubleshooting are in [docs/runbooks/refact-integration.md](../runbooks/refact-integration.md).

**Not supported yet:** Refact's planner, fleets and subagents. A subagent's first loop runs tools with no `PreToolUse` hook ([JegernOUTT/refact#35](https://github.com/JegernOUTT/refact/issues/35), tracked in #254).

Found on the way, and fixed for **every** host: the hook recorded no verdict when an agent quoted the `completion.py` path, which would have refused every write on an authorized issue.

## The ADR-006 floor is enforced (#181)

`--validate` re-derives the three floor indicators and refuses `CONDITION_BELOW_FLOOR` when a floored repository declares a level or profile below L4 / `GOVERNOR_HIGH_ASSURANCE`. Above the floor the level stays the human's choice. `generated_consumers` now reads tracked files only: a gitignored `node_modules/**/generated` used to floor a repository.

This repository was below its own floor. Its release tags raise `public_api_surface`, and it is now declared L4 / `GOVERNOR_HIGH_ASSURANCE`.

## An installed copy can be upgraded (#258)

An install made the documented way sat on a detached HEAD whose `origin` was a deleted temporary clone, so the documented upgrade failed. The installer now points `origin` at this repository, records the installed tag, and adds `--prune`. The upgrade is `git fetch --tags origin && git checkout --force vX.Y.Z && bash tools/install-skill.sh --prune .`. See [docs/runbooks/upgrade-and-uninstall.md](../runbooks/upgrade-and-uninstall.md).

**Upgrading from v0.7.0 itself needs a delete and reinstall once**, because v0.7.0's installer has no `--prune`. The runbook gives that path.

## Documentation matches the code, and drift is guarded (#256)

An audit of all 86 documents found the counts and safety claims correct, and drift in prose no suite read. It is fixed, and three drift classes now fail a suite: `SKILL.md`'s version (v0.7.0 shipped saying 0.6.0), the list of live suites in `AGENTS.md`, and every relative link and anchor in the documentation. The hook's block message now cites INV-014 and ADR-005 instead of a proposed invariant. Every engine CLI answers `--help`.

## Upgrading

- Run `engine/manifest.py --validate` after upgrading. `CONDITION_BELOW_FLOOR` means the declared level is below what the repository's obligations require; raise it, since the floor cannot be overridden downward.
- Refact users: follow the runbook's trust and blocking steps. Advisory mode does nothing on Refact.
